# 角色分工總覽

每份角色文件都寫成**可以直接當 prompt 使用**的格式：把整份文件（連同 `00_共同規範.md`）貼給 AI 代理，或交給負責的組員，就能照著執行。

## 如何使用

1. 先讀 [`00_共同規範.md`](00_共同規範.md)：所有角色都必須遵守。
2. 再讀自己的角色文件。
3. 單一事實來源（Single Source of Truth）：
   - 玩法規則 → `香菜退散_Godot遊戲企劃書.md`（由遊戲企劃維護）
   - v1.0 分析紀錄 → `docs/企劃分析與待確認事項.md`（問題已全部定案）
   - 決策紀錄 → `docs/decisions.md`（由製作人維護）
   - 資產製作流程 → `docs/pipeline/`（Tripo3D 料理建模流程與 prompt 範本）

## 用 Claude Code 開角色 session

每個角色在 `.claude/agents/` 都有對應的定義（名稱見下表的 Agent 欄），repo 根目錄的 `CLAUDE.md` 會在每個 session 開啟時自動載入共同規則。

- **網頁版／手機（claude.ai/code）**：選這個 repo 開新 session，第一句話指定角色與任務，例如：
  ```text
  你是 gameplay-programmer。照 .claude/agents/gameplay-programmer.md 和 docs/roles/06_遊戲邏輯程式.md 工作。
  任務：完成 M0 技術驗證（企劃書 9.2），完成後開 PR 到 main。
  ```
- **本機終端機**：每個角色用獨立的 worktree，並直接以角色身分啟動，例如：
  ```bash
  claude --worktree programmer-m0 --agent gameplay-programmer
  ```
- **同一個 session 內委派**：「請用 level-designer 子代理規劃 1-5 的香菜配置」。

各 session 之間不會自動同步，成果透過 PR 合併到 `main` 後，其他角色 `git pull origin main` 才看得到。

| Agent 名稱 | 角色 |
|---|---|
| `producer` | 01 製作人 |
| `game-designer` | 02 遊戲企劃 |
| `level-designer` | 03 關卡設計 |
| `artist-3d` | 04 3D 美術 |
| `ui-ux-designer` | 05 UI／UX 設計 |
| `gameplay-programmer` | 06 遊戲邏輯程式 |
| `sound-designer` | 07 音效設計 |
| `qa-tester` | 08 測試遊玩 |

## 開發流程與交接

```text
          ┌────────── 01 製作人：範圍／時程／決策 ──────────┐
          ▼                                              │
   02 遊戲企劃 ──規格──▶ 06 遊戲邏輯程式 ◀──資源── 04 3D美術
      │                      ▲   ▲                    ▲
      │規則                  │   │                    │
      ▼                      │   │UI場景              │視覺需求
   03 關卡設計 ──LevelData───┘   └── 05 UI/UX ◀──────┘
                                     ▲
                       07 音效 ──────┘（音效事件掛在訊號上）
                                     │
          08 測試遊玩 ◀──每週可玩版本──┘ ──Bug／試玩報告──▶ 01／02／06
```

| 里程碑 | 主導角色 | 主要協作 | 進入下一階段的條件 |
|---|---|---|---|
| M0 技術驗證 | 06 程式 | 08 QA | 方塊能拿起、物理放下並停穩；方塊在水中浮沉、能被攪動 |
| M1 操作原型 | 06 程式 | 02 企劃、05 UI/UX | QA 確認灰盒能選取、檢查、物理放下到任意位置 |
| M2 核心循環 | 06 程式 | 02 企劃、03 關卡 | 一份滷肉飯或水餃可以完整清除，計數正確 |
| M3 湯液系統 | 06 程式、04 美術 | 02 企劃、07 音效 | 一碗牛肉麵可以完整清除，包括漂浮與沉底的香菜 |
| M4 關卡與 UI | 03 關卡、05 UI/UX | 06 程式 | 從主選單到結算，6 關都能玩完 |
| M5 美術與打磨 | 04 美術、07 音效 | 06 程式、05 UI/UX | 灰盒資產全部替換，回饋完整 |
| M6 測試與交付 | 08 QA | 全員 | 附錄 A 完成定義全部打勾，沒有 P0／P1 bug |

> 決策紀錄：[`docs/decisions.md`](../decisions.md)。企劃書目前版本：v1.2。
