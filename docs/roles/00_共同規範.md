# 00 共同規範（所有角色必讀）

> 本文件是每個角色 prompt 的前置內容。角色文件與本文件衝突時，以**本文件**為準；本文件與企劃書衝突時，請停下來回報給製作人，不要自行決定。

## 專案背景

你參與的專案是《香菜退散！》（Cilantro Hunter），一款 Godot 4.x 的 3D Q 版休閒尋物遊戲：玩家把料理中的食物拿起、翻轉、觀察，找出黏在上面的香菜，再用筷子或鑷子挑掉。單局 1–3 分鐘，先做 PC 滑鼠版。

**MVP 範圍：** 3 道料理（滷肉飯、水餃、牛肉麵）、6 個關卡、2 種餐具（筷子、鑷子），以及完整的「拿取 → 檢查 → 挑除 → 結算」循環。

## 設計支柱（任何產出都不可違反）

1. **可辨識**：不看文字也能認出食材和香菜。
2. **可操作**：第一次玩的人看完簡短教學就能完成流程。
3. **有手感**：夾取、拉起、丟棄都有動畫和音效回饋。
4. **可重玩**：同一道料理再玩一次，搜尋過程不完全一樣。

## 工作原則

1. **範圍紀律**：只做 P0／P1 的內容。想到 P2 的點子，記到 `docs/backlog.md`，不要實作。
2. **先灰盒再精修**：先用簡單幾何體證明好玩，再投入正式資產。
3. **每週可玩**：每週交付一個能玩的增量；用「能玩到什麼」衡量進度，不用「做了幾個模型」。
4. **不自行假設**：遇到企劃沒定義的事，先查 `docs/企劃分析與待確認事項.md` 有沒有建議預設。有就照預設做，並在交付說明中註明「依預設 #編號」；沒有就提問，不要猜。
5. **小步提交**：一次變更只做一件事，說得清楚做了什麼、為什麼這樣做。
6. **可驗證**：每份交付都附上「怎麼確認它是對的」（測試步驟、截圖、數據）。

## 共用技術約定

- 引擎版本固定為一個 Godot 4.x 小版本（見待確認 D1），不得中途升級。
- 碰撞層：1 環境／桌面、2 可拿取食物、3 香菜目標、4 棄置碟、5 餐具、6 誘餌配料（建議新增）、7 暫放盤（建議新增）。
- 玩家看得到的字串一律用 `tr()` 或翻譯鍵，不要寫死在程式或場景裡。
- 二進位資產（`.glb`、`.png`、`.wav`、`.ogg`）由 Git LFS 管理；`.godot/` 不進版控。

## 問題嚴重度（全專案通用）

| 等級 | 定義 | 範例 |
|---|---|---|
| P0 阻斷 | 無法繼續遊玩或流程卡死 | 清完香菜卻不結算 |

| P3 輕微 | 小瑕疵或建議 | 按鈕音效偏大聲 |
