# 00 共同規範（所有角色必讀）

> 本文件是每個角色 prompt 的前置內容。角色文件與本文件衝突時，以**本文件**為準；本文件與企劃書衝突時，請停下來回報給製作人，不要自行決定。

## 專案背景

你參與的專案是《香菜退散！》（Cilantro Hunter），一款 Godot 4.5 的 3D Q 版休閒尋物遊戲：玩家把料理中的食物拿起、翻轉、觀察，找出黏在上面、漂在湯面或沉在湯底的香菜，再用筷子、鑷子或湯匙挑掉或撈起。食物放下時遵循物理，依位置與形狀自然落下停穩；湯有擬真的浮力、漣漪與攪動。單局 1–3 分鐘，先做 PC 滑鼠版。

**風格原則：外觀 Q 版，行為擬真。** 東西怎麼掉、怎麼浮、怎麼沉，都要符合玩家的生活經驗。

**MVP 範圍：** 3 道料理（滷肉飯、水餃、牛肉麵）、6 個關卡、3 種餐具（筷子、鑷子、湯匙）、物理放下、湯液系統，以及完整的「拿取 → 檢查 → 挑除 → 結算」循環。

**單一事實來源：** 企劃書 `香菜退散_Godot遊戲企劃書.md`（目前 v1.1）與決策紀錄 `docs/decisions.md`。

## 設計支柱（任何產出都不可違反）

1. **可辨識**：不看文字也能認出食材和香菜。
2. **可操作**：第一次玩的人看完簡短教學就能完成流程。
3. **有手感**：夾取、拉起、丟棄都有動畫和音效回饋。
4. **可重玩**：同一道料理再玩一次，搜尋過程不完全一樣。

## 工作原則

1. **範圍紀律**：只做 P0／P1 的內容。想到 P2 的點子，記到 `docs/backlog.md`，不要實作。
2. **先灰盒再精修**：先用簡單幾何體證明好玩，再投入正式資產。
3. **每週可玩**：每週交付一個能玩的增量；用「能玩到什麼」衡量進度，不用「做了幾個模型」。
4. **不自行假設**：遇到企劃沒定義的事，先查企劃書 v1.1 與 `docs/decisions.md`。有寫就照做，並在交付說明中註明「依決策 D-…」；沒有就提問，不要猜。
5. **小步提交**：一次變更只做一件事，說得清楚做了什麼、為什麼這樣做。
6. **可驗證**：每份交付都附上「怎麼確認它是對的」（測試步驟、截圖、數據）。

## 共用技術約定

- 引擎固定為 Godot 4.5.x（同一個小版本），物理引擎為 Jolt Physics，不得中途升級。
- 碰撞層：1 環境／桌面／固定容器、2 可拿取食物、3 香菜目標、4 棄置碟、5 餐具、6 誘餌配料、7 暫放盤、8 湯液體積。
- 物理與湯液的參數（密度、摩擦、阻尼、浮力）一律放在 Resource，不寫死在程式裡。
- 玩家看得到的字串一律用 `tr()` 或翻譯鍵，不要寫死在程式或場景裡。
- 二進位資產（`.glb`、`.png`、`.wav`、`.ogg`）由 Git LFS 管理；`.godot/` 不進版控。

## 問題嚴重度（全專案通用）

| 等級 | 定義 | 範例 |
|---|---|---|
| P0 阻斷 | 無法繼續遊玩或流程卡死 | 清完香菜卻不結算 |
| P1 嚴重 | 核心體驗錯誤，但有繞過方法 | 香菜旋轉時漂浮、計數重複 |

| P3 輕微 | 小瑕疵或建議 | 按鈕音效偏大聲 |
